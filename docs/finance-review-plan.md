**Financial basis for the changes**

Bond cash-flow timing matters: the traded clean price excludes accrued interest, while settlement uses a price including accrued interest. The current inputs cannot resolve that distinction. [Borsa Italiana: clean price](https://www.borsaitaliana.it/borsa/glossario/corso-secco.html). Coupon structure must be taken from the instrument: BTP Valore can pay semiannually or quarterly with step-up coupons. [Banca d'Italia: government securities](https://www.bancaditalia.it/compiti/operazioni-mef/index.html?com.dotmarketing.htmlpage.language=102). Treat unknown schedules as unavailable rather than fabricating payment dates.

Fund and trading currencies do not establish an ETF's underlying currency risk. The radar needs asset exposure information and a separate valuation currency. [justETF: currency risk](https://www.justetf.com/en-be/news/etf/the-effect-of-currencies-on-etfs.html).

Tracking difference measures realized deviation from the benchmark and can reflect fees, replication and securities lending. TER and tracking difference should not be presented as independent additive costs. Keep descriptive fund quality scores separate from expected-return claims. [Fidelity: tracking difference and tracking error](https://www.fidelity.com/learning-center/investment-products/etf/tracking-error-and-tracking-difference).

Withdrawal sustainability depends on horizon and portfolio assumptions. Use the FIRE calculator for sensitivity analysis, not a guarantee. [Morningstar: withdrawal rates and early retirement](https://www.morningstar.com/retirement/how-much-can-you-safely-withdraw-if-you-retire-early).

**Implementation sequence**

1. **Protect settings and align existing calculations — first release, small/medium scope.** Fix config authorization, archived-position filtering, independent target/PAC edits, reserve consistency, strict ETF hedge matching and hidden balances. Make unsupported exposure and bond outputs visibly unavailable or approximate immediately. Keep compatibility with existing records; if existing target/PAC fields already match, do not invent their historical intent. Acceptance: unauthenticated/non-admin settings writes fail in auth mode; one active holding is 100%; PAC changes never change targets; every reserve view agrees; unknown exposure never becomes Italy by default.

2. **Establish trustworthy market-data inputs — medium scope.** Validate chart data before replacement, show observation dates and sources, guard request races, and expose freshness/coverage for derived metrics and AI tools. Fix market-context refresh so repeated requests share an in-flight refresh, preserve per-source warnings, and do not silently satisfy a long-history request from a shorter cache. Keep explicit on-demand ETF refresh. Acceptance: malformed/empty provider results leave existing data intact; old responses cannot populate another ISIN; missing FX prevents a consolidated valuation rather than assuming parity.

3. **Repair the BTP calculator — medium/large scope, depends on reliable terms.** Implement dated fixed-coupon and zero-coupon cash flows first, with issue-specific payment conventions, accrued interest, settlement, redemption and transaction costs. Drive the modal and ranker from the same backend result. Include tradable nominal increments and residual cash. Validate yield by repricing to the supplied dirty price, and duration against a small parallel yield bump. Compare several dated reference examples with an authoritative source. Keep step-up/floating/indexed products out of precise rankings until their schedules/indexation are available. “Liquidity” should remain a labelled heuristic unless actual spread/volume data is acquired.

4. **Add real portfolio performance — larger optional capability, after the corrections.** Current `PerformanceResult` is `(value − invested) / invested`; this is an unrealized gain proxy, not a cash-flow-adjusted investment return. Label it accordingly now. Add a minimal dated ledger for contributions, withdrawals, internal transfers, buys/sells, distributions, fees and taxes, with manual entry and previewable CSV import. Preserve currency and valuations; reconcile balances with snapshots. Start with net contributions, realized/unrealized gain, distributions and a money-weighted return/XIRR. Only add true time-weighted return when valuations around external flows exist. Internal transfers must not count as portfolio contributions; reject or explain undefined/ambiguous IRRs. Acceptance: a €1,000 deposit into €10,000 with no market change shows €11,000 wealth and zero investment gain; reinvested dividends are not counted twice. [GIPS methodology](https://www.gipsstandards.org/standards/gips-standards-for-firms/gips-standards-handbook-for-firms/) distinguishes money-weighted returns from time-weighted returns that neutralize external cash flows. This is methodology guidance, not a proposal to claim GIPS compliance.

5. **Make the planning tools useful — medium scope, build incrementally.** Add a contribution-first rebalance preview: allocate a new cash budget to target shortfalls without automatically proposing sales. Where selling is considered, show user-configured estimated tax/fees and a switching break-even horizon; lower TER alone is insufficient justification. Separate spendable cash interest/coupons/dividends from embedded fund expenses. Add optional earmarked cash, liquidity restrictions and liabilities; until liabilities exist, label totals as tracked assets rather than comprehensive net worth. Add real-return scenarios using `(1 + nominal return) / (1 + inflation) − 1`, with matched periods. Keep Italian tax outputs explicitly estimated and instrument/regime-specific; defer a full tax engine pending verified requirements.

6. **Improve resilience and usability — small/medium scope alongside later releases.** Split heavy optional views with the existing platform tools; load essential account data independently from the entire instrument catalog; show partial failures without blocking the dashboard. Reuse the current money/date utilities, show values and observations with their currencies, and maintain keyboard access in inline editors/charts. Make JSON exports transactionally consistent and CSV cells safe for spreadsheet interpretation. Update the README's stale run/refresh descriptions. Avoid a broad UI rewrite or new state-management framework.

**Additional high-value finance feature**

Deposit concentration alerts should group eligible deposits by the actual banking entity and depositor ownership, not by account name. FITD's ordinary limit is €100,000 per depositor per bank; multiple accounts at one bank do not multiply it, and not all broker balances or financial instruments are covered deposits. Add coverage only when institution/scheme/ownership metadata is known; otherwise display “coverage unknown.” [FITD guarantee rules](https://www.fitd.it/Cosa_facciamo/Garanzia_dei_depositanti). This can follow the account-model corrections without waiting for the performance ledger.

**Scope and completion gates**

Start with steps 1–2. They correct existing outputs with the smallest changes. Do not add optimization engines, forecast-driven trading recommendations, Monte Carlo infrastructure, automatic trades, or broad broker integrations to this plan's first release. Step 4 is the largest product decision and should be a separate milestone.

For each calculation change, add the smallest regression case that fails on the demonstrated error, then run the existing suite. For new persisted fields, include migration and backup round-trip coverage. Check the relevant screens with synthetic EUR/USD, archived-account, missing-price and zero-cost-basis examples. No dependency or architecture replacement is required for the first release.
